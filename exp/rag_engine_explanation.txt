🏗️ ARCHITECTURE & PURPOSE:
----------------------------
Core RAG (Retrieval-Augmented Generation) engine that combines:
• Vector similarity search for knowledge retrieval
• LLM integration for intelligent response generation
• Document processing and chunking
• Secure configuration and error handling
• Performance optimization with caching

⚙️ METHODS/FUNCTIONS:
---------------------

1. load_llm(max_tokens: int = 4096):
   • Purpose: Initialize Groq LLM with secure configuration
   • Parameters: max_tokens (int) - Maximum response tokens
   • Returns: ChatGroq instance or None
   • Work:
     - Loads API key from secure config
     - Creates ChatGroq instance with model configuration
     - Sets temperature and token limits
     - Implements comprehensive error handling
     - Logs initialization success/failure
   • Security: API key from environment, never hardcoded
   • Performance: Connection reuse and optimized settings

2. initialize_vector_store():
   • Purpose: Initialize or rebuild FAISS vector store
   • Parameters: None
   • Returns: FAISS vector store or None
   • Work:
     - Loads HuggingFace embeddings model
     - Checks for existing vector store
     - Compares knowledge base modification time
     - Rebuilds vector store if needed
     - Implements timestamp-based cache invalidation
     - Handles document loading and chunking
     - Saves vector store to disk with timestamp
   • Security: Validates file paths and handles errors
   • Performance: Persistent storage with intelligent rebuilding

3. _build_vector_store(embeddings, kb_modified_time):
   • Purpose: Build vector store from scratch
   • Parameters: embeddings (HuggingFaceEmbeddings), kb_modified_time (float)
   • Returns: FAISS vector store or None
   • Work:
     - Loads knowledge base from text file
     - Splits documents into chunks (500 chars, 50 overlap)
     - Creates FAISS vector store from chunks
     - Saves vector store to persistent storage
     - Records build timestamp for cache validation
     - Shows progress indicators to user
   • Performance: Efficient chunking and vectorization
   • Error Handling: Graceful fallback on failures

4. get_rag_chain(llm, vector_store):
   • Purpose: Create RAG question-answering chain
   • Parameters: llm (ChatGroq), vector_store (FAISS)
   • Returns: RetrievalQA chain
   • Work:
     - Creates prompt template for Shifu persona
     - Configures vector store as retriever (k=3 documents)
     - Sets up RetrievalQA chain with components
     - Configures chain type and return options
     - Integrates prompt template for consistent responses
   • Performance: Optimized retrieval with limited document count

5. extract_intent_and_contact(query, response):
   • Purpose: Extract user intent and contact information
   • Parameters: query (str), response (str)
   • Returns: Tuple (intent, contact_info)
   • Work:
     - Validates and sanitizes user query
     - Performs keyword-based intent classification
     - Identifies course/learning vs contact inquiries
     - Returns structured intent data
     - Logs classification results
   • Security: Input validation through SecurityValidator
   • Intelligence: Context-aware intent recognition
